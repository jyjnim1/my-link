# 마이링크 (MyLink) 제품 요구사항 정의서 (PRD)

## 1. 프로젝트 개요
- **프로젝트명**: 마이링크 (MyLink)
- **목적**: 인스타그램, 틱톡 등 단일 링크만 지원하는 플랫폼에서 여러 링크를 한데 모아 효과적으로 공유할 수 있는 서비스 (링크트리 클론)
- **대상 사용자**:
  - 다수의 채널(유튜브, 블로그, SNS 등)을 운영하는 크리에이터 및 인플루언서
  - 포트폴리오를 하나의 페이지로 정리하고 싶은 사용자
  - 상품 홍보가 필요한 소상공인 및 마케터
- **비즈니스 모델**: 완전 무료
- **UI/UX 방향성**: `shadcn/ui` 디자인 시스템을 활용한 직관적이고 모던한 UI 구현 (테마 커스텀 기능은 제공하지 않음)

## 2. 핵심 기능 목록

1. **사용자 인증 (Google 소셜 로그인)**
2. **프로필 관리** (이미지 업로드 없이 Display Name 및 소개글 인라인 편집)
3. **링크 관리** (생성, 조회, 인라인 수정, 삭제)
4. **공개 프로필 페이지** 제공 (`/[DisplayName]`)

---

## 3. 기능 상세 설명

### 3.1 사용자 인증 (구글 기반)
- **기능 설명**: 사용자가 번거로운 폼 작성 없이 구글 계정을 통해 즉시 가입하고 로그인할 수 있습니다.
- **상세 요건**:
  - 로컬 이메일/비밀번호 가입 로직을 배제하고 오직 Google OAuth 소셜 로그인만 지원합니다.
  - 최초 로그인 시 자동으로 회원가입이 연동 처리됩니다.
  - **초기값 자동 설정**: 회원가입 시, 사용자의 구글 지메일 아이디 앞부분(`@` 기호의 앞부분)을 추출해 해당 사용자의 고유한 `Display Name(디스플레이 네임)`으로 자동 설정합니다. (예: `hong123@gmail.com` -> `hong123`)

### 3.2 프로필 관리
- **기능 설명**: 사용자 방문 시 최상단에 노출될 개인화된 명함을 설정합니다. 별도의 이미지 직접 업로드 기능은 제공하지 않습니다.
- **상세 요건**:
  - 별도의 수정 폼 팝업이나 페이지 이동 없이 텍스트를 즉시 변경할 수 있는 **인라인 편집(Inline Editing)** 방식을 채택합니다.
  - 사용자는 다음 정보를 인라인으로 자유롭게 수정할 수 있습니다:
    - **Display Name(디스플레이 네임)**: 화면에 보여지는 실제 유저의 이름이자 퍼블릭 URL의 식별자(Slug)로 동시 사용됩니다.
    - **Bio(바이오)**: 본인을 소개하는 짧은 문구

### 3.3 링크 관리 (CRUD)
- **기능 설명**: 프로필에 노출할 다양한 URL 링크를 등록하고 관리합니다.
- **상세 요건**:
  - **생성**: 연결될 외부 URL과 화면에 표시할 제목을 입력하여 새로운 링크 엘리먼트를 추가합니다.
  - **수정**: 등록된 URL이나 제목 부분의 텍스트를 클릭 시 곧바로 입력창으로 전환되는 **인라인 편집** 기능으로 즉각적인 수정이 가능합니다.
  - **삭제**: 더 이상 필요 없는 버튼의 경우 즉시 삭제가 가능합니다.
  - **파비콘(Favicon) 연동**: 구글 파비콘 API (Google Favicon API)를 사용하여 등록된 대상 URL의 파비콘 이미지를 연동해 링크 버튼 내 아이콘 이미지로 자동 노출시킵니다.

### 3.4 공개 프로필 페이지 (Public Profile View)
- **기능 설명**: 실제 방문자가 접속해 사용자의 링크를 확인하고 접속할 수 있는 페이지입니다.
- **상세 요건**:
  - 사용자 본인의 **`Display Name`**을 URL Slug로 그대로 차용하여 `/디스플레이네임` 형식(예: `도메인.com/hong123`)의 직관적인 사용자 맞춤형 URL을 제공합니다.
  - 다양한 스마트폰 접속 환경에 맞춰 깨지지 않는 모바일 퍼스트(Mobile First) 반응형 UI를 적용합니다.

## 4. 데이터베이스 모델링 요구사항
- **User 모델**: 사용자의 인증 및 기본 정보를 정의합니다. 다음 필드들이 기획의 핵심입니다:
  - `displayName`: 화면에 노출됨과 동시에 URL Slug 식별자로 사용되는 통합 속성 (구글 이메일 앞부분으로 초기 생성)
- **Sub-collections 활용**: 해당 사용자에게 속한 개별 링크 데이터는 데이터베이스 구성 시 고정 배열 필드가 아닌 서브 컬렉션(Sub-collections) 방식으로 설계해 데이터의 입출력 및 관리에 대한 퍼포먼스를 보장합니다.

---

## 5. 추후 추가 예정 기능
- **링크 클릭 조회수 통계**: 사용자 개인 페이지의 방문 기록이나 세부 통계는 제공하지 않지만, 각 링크별로 방문자가 얼마나 클릭했는지 숫자로 확인할 수 있는 조회수(Count) 수집 기능은 추후 개발하여 추가할 예정입니다.
